# 2026-10-30 程序检查与认证集成

> 此文是 1.x 的历史检查记录。原实现现归档在 `legacy/powershell/`；当前版本的安装和操作以根目录 README 及 `docs/migration.md` 为准。

检查对象：`hikvision-asmp-tools`，原始 Git 提交 `724612a`。对照了用户提供的收货登记截图、官网当前静态脚本，并由用户在新版软件内完成了一次真实登录。

## 已确认问题与修复

| 问题 | 原行为与影响 | 修复 |
| --- | --- | --- |
| 超时后可能重复登记 | 非幂等提交失败均记为“失败”；服务器可能已经创建工单，重试会再提交 | 请求前写入持久意图；无法确认结果时标为待核对并阻止直接重试 |
| 历史成功记录可被覆盖 | `Read-Records` 只保留最后结果；后一次失败会抹去此前成功 | 保留历史成功；同时优先保护后一次待核对提交 |
| 取消去重后批内重复提交 | 输入重复项未去重，取消跳过历史记录后会重复发送 | 每批独立去重，不依赖历史跳过开关 |
| 多实例同时提交 | 两个程序可同时读取同一旧 CSV 后提交 | 每目录单实例互斥锁 |
| 记录写入/读取失败继续提交 | 写记录失败只打日志、读记录失败返回空表，会丢失防重复依据 | 意图记录写入失败不发送；损坏或不可读的 CSV 停止任务 |
| HTTP 失败可能被判成功 | 只检查 JSON `code=000`，不要求 HTTP 成功状态 | 同时要求 HTTP 2xx 和业务成功码；异常响应归为不确定 |
| 登录失效码不完整 | 仅识别 013 和部分文字；漏掉官网拦截的 003 | 识别 003/013、401/403，失效停止整批任务 |
| 停止不及时 | HTTP 与延迟在界面线程同步等待；查询后的提交前也未重新判断停止 | 异步 HTTP 任务配合消息循环，查询后重新检查；已发送的提交等待结果 |
| 关闭/异常可中断任务清理 | 请求间可关闭表单，缺少统一 finally 恢复按钮 | 任务期间关闭只请求停止，finally 恢复控件 |
| 令牌以明文保存 | `submit_config.json` 保存 token，输入框直接显示 | 会话内存保存、隐藏输入；迁移旧 token 并移除明文配置项 |
| 查询内容被错误覆盖 | `isExchangeAmountMaterial` 缺省为 1，而网页为 0；`xltyp`、质检、附件被清空 | 按官网字段映射保留返回资料，交换标志缺省改为 0，不再凭空补零价格 |
| 输入和配置缺少校验 | 拼接 serial JSON；必填信息、枚举、间隔缺少校验，极大数字会溢出 | JSON 序列化、输入校验、枚举与范围校验；空配置阻止提交 |
| 处理方式缺少账号/产品约束 | 软件可传入网页不允许的处理方式；一年包换却没有更换方式 | 校验 SR02、网点固定本地服务条件及一年包换条件，缺少更换方式则引导网页处理 |
| 日志保存完整业务报文 | 原日志含整份客户、电话、地址和服务端资料 | 默认只记录必要的步骤、序列号和结果，不记录完整业务报文 |

## 认证流程证据

官网根目录是另一套应用，真正的送修入口为 `/sr/`。截至检查时：

- [送修系统主脚本](https://asmp.hikvision.com/sr/static/js/app.6bacefba.js) 定义 `tokenKey="asmp_sr_token"`。
- 登录模块向 `/api/sendRepairWeb/logindeal/toLogin` POST `{name, password}`。成功后从 `data.accessToken` 写入上述 Cookie。
- 请求拦截器读取该 Cookie，并放入 `accessToken` 请求标头；业务码 003 触发跳转。
- [登录页面脚本](https://asmp.hikvision.com/sr/static/js/chunk-7c689da9.8a4764a7.js) 包含账号、密码及首次登录修改资料等官网流程。
- [收货登记脚本](https://asmp.hikvision.com/sr/static/js/chunk-47626014.ca447c69.js) 确认字段映射、处理方式枚举、账号能力限制、`isExchangeAmountMaterial || 0`、提交状态和短信字段。

实现通过 [WebView2 CookieManager](https://learn.microsoft.com/en-us/dotnet/api/microsoft.web.webview2.core.corewebview2cookiemanager.getcookiesasync) 读取官方 Cookie，不重写官网密码处理、不读取账号密码。仅允许 ASMP 官方 HTTPS 顶层导航，不允许凭据请求跨域重定向；使用 InPrivate 会话。

无需更换 Python。保留 Windows 自带 PowerShell 5.1，增加一个小型 C# WinForms 浏览器控件，现有配置范围不变。微软 SDK 版本、下载地址与包摘要记录在 `lib/sdk-source.json`。

## 验证与边界

- 核心离线回归覆盖输入、报文字段、HTTP/业务码、CSV 往返、历史成功保护、待核对保护、超时/空响应/HTML/500、停止、记录锁定及账号条件。
- Windows PowerShell 5.1 下编译并运行登录控件；WebView2 InPrivate 实际载入官方登录页通过。
- 主窗口在独立测试目录启动、保存配置并退出通过；验证配置不包含 token。
- 用户在软件内完成真实登录。软件取得 Cookie 并调用只读 `/base/getLoginInfo`，返回认证成功；检查文件只有 `authenticated:true`，未保存凭据。
- 未创建实际维修登记，未验证某条真实序列号的提交结果。实际登记的最终报文及后台返回仍需要业务数据联调，不能把模拟测试当作生产提交成功。
- 现有浏览器的自动化访问因工具无法可靠确定 Windows 当前网址而中止，因此未对已登录浏览器做逐控件操作评估。页面字段评估依据用户截图和官网发布脚本。
- 本地 CSV 只能保护该目录的记录；服务端未确认提供幂等键，跨电脑/网页重复登记仍需历史数据核对。
