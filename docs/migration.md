# 配置、升级与记录核对

## 从 Python 2.0 升级到 2.1

关闭旧版后运行新版，仍使用相同的系统用户数据目录，原设置和成功/待核对记录自动保留。旧配置缺少 `isSend` 时使用原行为“寄回送修点”（`1`），不会自动改成寄回客户。

2.1 将数据库升级到 schema 2，增加每次提交使用的故障描述及频次表。2.0 无法打开升级后的数据库；如需回退，请在升级前关闭程序并备份整个数据目录。旧版本没有逐次保存故障描述，所以历史次数从升级后的成功登记开始统计，不根据旧记录猜测或回填。

## 从 PowerShell 1.x 升级

1. 关闭旧版程序，保留 `submit_config.json` 和 `submit_records.csv`。
2. 将两个文件放在 Python 源码目录或 Windows 新版 EXE 所在目录，再启动新版。
3. 程序把设置和记录迁入系统用户数据目录，旧 CSV 原件保持不变。
4. 先检查迁移后的设置和历史记录，再进行只读查询或登记。

也可以显式指定旧目录：

```bash
python run.py --legacy-dir "/path/to/old-tool"
```

Windows 原生包使用 `HikvisionASMP.exe --legacy-dir "D:\old-tool"`；macOS 可运行 `.app/Contents/MacOS/HikvisionASMP` 并传入同一参数。

相同旧 CSV 不会重复导入；新增行可以增量迁移。已经导入的历史行被改写、文件截断或状态无法识别时，会停止迁移，避免丢失防重复依据。

旧配置的 token 仅移入本次内存会话，保存时移除明文字段。新配置没有 token 字段。首次登录依然建议使用官方网页登录。

## 保留的设置

| JSON 键 | 含义 |
| --- | --- |
| `repairClient` | 送修客户 |
| `linkman` / `linknumber` | 联系人 / 联系电话 |
| `rebackFault` / `rebackFaulttext` | 客户反馈故障 / 故障描述 |
| `dealType` | `0` 维修、`1` 一年包换、`2` 本地服务 |
| `repairMode` | `0` 送修、`1` 上门取件、`2` 寄修 |
| `isSend` | `1` 寄回送修点（默认）、`0` 寄回客户；写入报文表头及每条明细 |
| `province` / `city` / `area` / `address` | 寄回客户的省、市、区名称及详细地址；寄回客户时必填 |
| `delay` | `0`–`600000` 毫秒的整数；兼容旧版数字字符串 |
| `skip` | 是否跳过历史成功记录，默认 `true` |

模板为 [`submit_config.example.json`](../submit_config.example.json)。短信通知仍关闭；型号、保修、客户、质检和物料信息来自查询结果。选择“寄回客户”后，在登录状态下点击“加载省市区”，依次选择地址。切换省/市会清除下级选择，加载失败可重试；切回“寄回送修点”后地址仍在本地保留，但不随该类登记发送。

登记设置编辑后约 0.6 秒自动保存，也在任务开始前和正常关闭时保存。尚未填完整的表单可以保存，但正式提交仍须通过必填校验。保存成功与失败均在登记设置下方显示；失败时请检查数据目录权限，点击“保存设置”重试。令牌始终不写入配置。

## 故障描述历史

输入新描述或从下拉框选择已有描述。每个设备明确成功登记后，该描述使用次数增加 1；相同描述去除首尾空白后合并。排序先按次数降序，同次数按最近成功时间降序。待核对记录人工确认已登记后也计入一次；查询、明确失败、跳过和未核对记录不计入。

选择已有描述后点击“删除历史”立即从下拉框移除，删除结果也会保留到下次启动。当前输入及提交审计记录不受影响；以后再次成功使用时从 1 次开始累计。频次保存在同一 SQLite 数据库，随整个数据目录备份。

软件校验账号的收货登记权限及网点能力。网点在官网固定为“本地服务”时，软件也必须使用该方式。一年包换缺少更换方式或产品条件不符时，转到官网处理。

## 数据目录与备份

| 系统 | 默认目录 |
| --- | --- |
| Windows | `%LOCALAPPDATA%\HikvisionASMP` |
| macOS | `~/Library/Application Support/HikvisionASMP` |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/HikvisionASMP` |

主要文件为 `submit_config.json`、`submit_records.sqlite3`、SQLite 运行辅助文件和 `logs/`。关闭程序后备份整个目录，恢复时保持文件完整。不要在程序运行时仅复制单个数据库文件。

`--data-dir 路径` 可指定其他数据目录。不同目录的防重复记录相互独立；改用空目录不会带入原目录的历史。

## 结果与重试

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 成功 | 收到明确成功响应 | 默认跳过历史成功记录 |
| 明确拒绝 | 收到有效的业务拒绝响应 | 修正原因后重试 |
| 查询/校验失败 | 尚未发出对应登记请求 | 核对序列号和设置 |
| 登录失效 | 认证失效，任务停止 | 重新登录 |
| 提交中 / 待核对 | 已保存提交意图，结果尚不明确 | 先在官网历史数据核对 |

登记请求不会自动重放。取消历史成功跳过开关，也不会绕过待核对保护。早期 1.x 曾将提交超时记为“失败”；迁移时，缺少明确拒绝依据的旧失败记录按待核对处理。

在官网查明对应登记后，选中本地记录，点击“核对：已登记”或“核对：未登记”并填写说明。程序保存核对事件；已有终态记录不允许任意改写。

历史成功与后一次失败分别保留；如果后一次提交仍不明确，仍需核对。当前目录的本地记录不能覆盖另一台电脑或网页端的全部登记。

## 导出与日志

记录页显示最近 2000 条筛选结果，CSV 导出包含全部匹配记录。导出使用 UTF-8 BOM、标准 CSV 转义，并处理可能被表格软件解释为公式的单元格。

导出包含业务资料，日志也可能包含序列号。配置、记录、日志及令牌均不属于项目源码。提交问题时使用脱敏信息，保留 HTTP 状态和业务错误码即可，不发送真实令牌或客户资料。
